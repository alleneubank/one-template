# one-template

A [One](https://onestack.dev) app template for web, iOS, and Android, built on
[typescript-template](https://github.com/alleneubank/typescript-template): Bun
1.4.5 workspaces, a One 2.24 app in `apps/app`, silo and Tilt dev stacks, and
`bun run verify`, which drives the app with agent-browser and agent-device.

## Getting started

Create a repository from this template. With [mise](https://mise.jdx.dev)
installed and Docker running (OrbStack on macOS):

```sh
mise trust
mise install --locked
bun install
bun run setup      # prompts for the package scope, app name, and app id
bun install        # relink workspace packages under the new scope
bun run verify     # static checks, then the app on web, iOS, and Android
```

`setup` replaces the `@template` scope across every manifest and source file,
and writes the app name (Xcode project and Android app name, for example
`MyApp`) and the app id (iOS bundle id and Android application id, for example
`com.myorg.myapp`) into `apps/app/app.identity.ts`. It does not rewrite
`bun.lock` or the links already in `node_modules`, so `check` and `test` cannot
resolve the renamed packages until `bun install` runs again. It does not touch
the root `package.json` `name` or this README — update those by hand, and
replace or delete `LICENSE`, which covers the template rather than whatever you
build from it.

## Running the app

```sh
silo up            # one dev under Tilt, on the WEB_PORT silo assigns this worktree
cd apps/app
WEB_PORT=<port> bun run ios --udid <simulator udid>
WEB_PORT=<port> ANDROID_SERIAL=<emulator serial> bun run android
silo down
```

silo writes the ports it assigned to `.localnet.env`. Each worktree gets its own
ports, so several worktrees can run at once. The native apps load their
JavaScript from the dev server on `WEB_PORT`; `ios/` and `android/` are
generated by `one prebuild` on the first native run and are not committed.

## Verifying a change

`bun run verify` runs every leg; name legs to run only those, for example
`bun run verify static web`.

| Leg       | Proves                                                                                                                                   |
| --------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| `static`  | `check`, `test`, `knip`, `jscpd`, and `build` pass                                                                                       |
| `web`     | under `silo up`, agent-browser sees the home screen and the `/native` route                                                              |
| `ios`     | on a new simulator, `one run:ios` installs the app, and agent-device sees the home screen and `/native` answered by the Swift module     |
| `android` | on a new emulator, `one run:android` installs the app, and agent-device sees the home screen and `/native` answered by the Kotlin module |

Screenshots and logs land in `tmp/verify/`. Each native leg removes the
simulator or emulator it created. `--without-silo` starts `one dev` directly
instead of through silo, for hosts without Docker such as GitHub's macOS
runners. CI runs `static` through `ci.yml` and the other legs through
`verify.yml`.

The native legs need macOS with Xcode, an iOS simulator runtime, and CocoaPods
for iOS, and the Android SDK (with `cmdline-tools`, the emulator, and a
`google_apis` system image) and JDK 17–21 for Android. Set `ANDROID_HOME` if the
SDK is not at `~/Library/Android/sdk`, and `VERIFY_ANDROID_IMAGE` to pick a
system image. agent-browser needs a Chrome: run `agent-browser install`, or set
`AGENT_BROWSER_EXECUTABLE_PATH`. A cold native build takes tens of minutes;
later runs reuse the CocoaPods, Gradle, and Xcode caches.

## Merging typescript-template

This repository shares history with typescript-template. To take its changes:

```sh
git remote add template https://github.com/alleneubank/typescript-template.git
git fetch template
git merge template/main
bun install        # regenerate bun.lock if it conflicts
mise lock          # if mise.toml or mise.lock conflict
```

The files this template changes from typescript-template are `README.md`,
`package.json`, `mise.toml`, `mise.lock`, `knip.json`, `.oxfmtrc.jsonc`,
`tsconfig.json`, `.gitignore`, `bun.lock`, and `scripts/setup.ts`; expect
conflicts only there.

## Scripts

| Command                           | Does                                         |
| --------------------------------- | -------------------------------------------- |
| `bun install`                     | install dependencies from `bun.lock`         |
| `bun run check`                   | typecheck, lint, and format check            |
| `bun run test`                    | unit tests with `bun test`                   |
| `bun run verify`                  | static checks, then the app on each platform |
| `bun run build`                   | build every package with tsdown              |
| `bun run typecheck`               | `bun --check -b` across all projects         |
| `bun run lint` / `lint:fix`       | oxlint                                       |
| `bun run format` / `format:check` | oxfmt                                        |
| `bun run knip`                    | find unused files, exports, and dependencies |
| `bun run jscpd`                   | copy-paste detection                         |
| `bun run changeset`               | record a release note                        |

## Layout

```
apps/app/   the One app: routes in app/, native modules in native/
apps/       other private applications
packages/   publishable libraries
```

Packages build with tsdown into `dist/`, unbundled, as ESM and CJS with matching
declarations. `bun check` follows project references and leaves `dist/` to tsdown.

`isolatedDeclarations` is on, so exported symbols need explicit type
annotations. That is what lets tsdown generate declarations through oxc rather
than the TypeScript compiler.

## Adding a package

Copy a directory under `packages/`, then:

1. Keep the `<scope>/source` condition first in its `exports`, pointing at
   `./src/index.ts`. Typechecking resolves sibling packages from source through
   that condition, so `check` works before anything is built. Bun does not read
   `customConditions` from `tsconfig` at runtime, so `test` and `start` pass the
   same condition with `--conditions`.
2. Add it to `references` in the root `tsconfig.json`, and in the `tsconfig.json`
   of any package that imports it.

There is no central path map to update.

## Requirements

Bun 1.4.5 is the package manager, runtime, test runner, and type checker. The
pin lives in `mise.toml` and `engines.bun`. The lockfile is `bun.lock`.
Installs use a hoisted `node_modules` tree.

`mise.toml` and `mise.lock` pin Bun along with Tilt, lefthook, jq, ripgrep,
uutils coreutils, silo, janitor, Node, agent-browser, and agent-device, with a checksum for each platform's download. CI installs the
same lockfile through `jdx/mise-action`. Activate mise in your shell, prefix
commands with `mise exec --`, or review `.envrc` and run `direnv allow`; the
direnv integration also loads the optional `.env`, `.env.local`, and
`.envrc.private` files. On Linux, mise sets
`PLAYWRIGHT_SKIP_VALIDATE_HOST_REQUIREMENTS=true`. uutils ships one multicall
binary, so run its utilities as `coreutils <utility>`, for example
`coreutils sort`; plain `sort` stays the system one.

The weekly dependency workflow bumps the mise pins and `mise.lock` except Bun
and uutils coreutils, and runs on macOS so a pin without macOS builds fails
before it lands. Change Bun in `mise.toml`, `engines.bun`, and `@types/bun`
together, then run `mise lock`. coreutils stays on 0.12.0 because 0.13.0 ships
no macOS builds.
