# one-template

A One 2.24 app (`apps/app`) for web, iOS, and Android in a Bun monorepo derived
from typescript-template. README.md covers setup and every script; this file
covers what an agent needs to run, try, and prove a change.

## Toolchain

- `mise install --locked` installs every pinned tool, including silo, janitor,
  Tilt, Node, agent-browser, and agent-device. Run commands through mise
  (activated shell, `mise exec --`, or direnv).
- silo needs a running Docker engine (OrbStack on macOS) even though this
  project does not use k3d.
- One runs on Node. Do not run One commands with `bun --bun`, and do not add
  `[run] bun = true` to `bunfig.toml`; both crash One in `depd`.

## Run and try the app

- Web: `silo up` from the repository root starts `one dev` under Tilt on the
  `WEB_PORT` silo assigned to this worktree (read it from `.localnet.env`).
  Drive it with agent-browser at `http://localhost:$WEB_PORT`, using your own
  `--session`. Stop with `silo down`, then `silo down --clean`.
- iOS: with the dev server up, create a simulator
  (`xcrun simctl create <name> <device type> <runtime>`), then from `apps/app`
  run `WEB_PORT=$WEB_PORT bun run ios --udid <udid>`. Drive it with
  `agent-device open <app id> --platform ios --udid <udid>`. Delete the
  simulator by UDID when done.
- Android: start an emulator you created (`ANDROID_AVD_HOME` inside this
  worktree's `tmp/`), then from `apps/app` run
  `WEB_PORT=$WEB_PORT ANDROID_SERIAL=<serial> bun run android`. Drive it with
  `agent-device open <app id> --platform android --serial <serial>`. Kill the
  emulator by serial and delete its AVD when done.
- The app id and name live in `apps/app/app.identity.ts`. `ios/` and
  `android/` are generated by `one prebuild`; change `vite.config.ts` or
  `app.identity.ts` instead, then prebuild again.
- Native modules: Swift in `apps/app/native/AppNative/` (a Swift package),
  Kotlin in `apps/app/native/*.kt`. One generates the `*.d.swift.ts`,
  `*.d.kt.ts`, and `.one-native-source.*` files; commit them, do not edit them.
  `apps/app/features/native/device*.ts` picks the platform's module.
- Run `agent-device` with `AGENT_DEVICE_STATE_DIR` inside this worktree's
  `tmp/` so its daemon does not collide with other sessions'.

## What proves a change

`bun run verify [static] [web] [ios] [android]` (all legs when none are named).
Artifacts go to `tmp/verify/`.

- `static`: check, test, knip, jscpd, and build. Enough for a change with no
  runtime effect (docs, types, tooling config).
- `web`: required for any change under `apps/app` or to `silo.toml`,
  `Tiltfile`, or the dev server.
- `ios` and `android`: required for changes to native modules,
  `vite.config.ts`, `app.identity.ts`, native dependencies, or anything that
  renders on device. Each creates and removes its own simulator or emulator.
- `--without-silo` starts `one dev` directly; use it only where Docker cannot
  run. It does not prove the silo path.

CI runs `static` in `ci.yml` and the app legs in `verify.yml`.

## Merging typescript-template

This repository shares history with typescript-template; merge it, do not
rebase or copy files:

```sh
git remote add template https://github.com/alleneubank/typescript-template.git  # once
git fetch template
git merge template/main
```

Resolve `bun.lock` conflicts with `bun install` and `mise.lock` conflicts with
`mise lock`. Conflicts elsewhere are limited to the files this template changed:
`README.md`, `package.json`, `mise.toml`, `knip.json`, `.oxfmtrc.jsonc`,
`tsconfig.json`, `.gitignore`, and `scripts/setup.ts`. Run `bun run verify`
after the merge.
